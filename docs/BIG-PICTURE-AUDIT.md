# Big Picture reliability review

Review date: 16 November 2026. Applies to the working source for 4.4.1-remix.4.

This pass reviews Big Picture code, repairs confirmed defects, and tests isolated interactions. It does not establish that every possible bug is fixed or that every game starts correctly on every machine. The original three-minute startup could not be reproduced from code alone.

## Repairs

| Area               | Defect and resulting behavior                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Mouse input        | Controller mode disabled pointer events across the interface. Controls now remain hit-testable, and an explicit mouse press switches input mode even immediately after controller activity.                                                                                                                                                                                                                                   |
| Controller input   | A press could be consumed solely to restore an already valid focus. That press now activates the restored control. Recovering an unknown focus still avoids accidental activation. Releasing a held button after focus moves cannot activate a different control.                                                                                                                                                             |
| Keyboard input     | Enter could activate the last controller item instead of the native control with keyboard focus. Native controls now retain native activation.                                                                                                                                                                                                                                                                                |
| Launch feedback    | Normal game-page launches did not await the backend. They now propagate errors and show Starting while pending. Game-page, library, and download launch actions share a per-game reservation.                                                                                                                                                                                                                                 |
| Launch dispatch    | Windows shell errors and asynchronous native spawn errors could be ignored. Dispatch now waits for OS acceptance and reports failure. Simultaneous requests for the same game share one backend operation.                                                                                                                                                                                                                    |
| Process detection  | The launch reservation continues after dispatch until process detection, with a 60-second detection limit. Failure releases it for an explicit retry. There is no automatic retry. Existing deletion and cloud-save launch gates remain in place.                                                                                                                                                                             |
| Diagnostics        | Logs record request receipt, preparation, dispatch, failure, and process detection with elapsed time. Windows now reports detection as well as closing the launch window. An older launch window's close callback cannot clear the reference to its replacement.                                                                                                                                                              |
| Game metadata      | A failed optional statistics or artwork request could prevent the fallback game page from being created. Failed requests now produce a usable fallback and preserve the library title.                                                                                                                                                                                                                                        |
| Loading controls   | A loading button could still be an active navigation target. Loading now disables both native activation and spatial navigation.                                                                                                                                                                                                                                                                                              |
| Dialogs            | Busy dialogs could be dismissed through the close button or backdrop. Busy state now guards dismissal. Escape is handled by the topmost dialog without leaking into page navigation; non-dismissable dialogs also consume Back. Text-entry Escape continues to leave the field first.                                                                                                                                         |
| Asynchronous state | Delayed initial process/profile snapshots could overwrite newer events. Older library/backup refreshes could overwrite newer responses. Reads now respect event/request ordering and component disposal.                                                                                                                                                                                                                      |
| Achievements       | Game-page achievements were not refreshed after unlock notifications. They now refresh on unlock and library updates, reject stale responses, and clear the previous game's list when identity changes.                                                                                                                                                                                                                       |
| Backup paths       | Existing custom paths could initially appear blank, and a game deep link could repeatedly force selection back to its original game. Drafts now load saved paths, remain tied to their game, and require confirmation before discarding edits when switching games.                                                                                                                                                           |
| Backup safeguards  | Everyday Save backups exposes overview, discovery, and backup actions. Recovery, destination, retention, custom paths, and automatic-backup switches are reached through Advanced's acknowledgement gate and its backup category. Reduced retention and changed paths retain their acknowledgements; per-game disabling is named in the save confirmation. Undoing a default game's toggle restores the exact original draft. |
| Advanced tools     | Unlocked settings now open by category instead of presenting every sensitive control at once. Selecting or adding a website profile no longer reloads profiles and discards drafts. Website-data and search-order failures are reported instead of becoming unhandled rejections.                                                                                                                                             |

## Review coverage

The code sweep covered input/focus services, modal controls, home/catalogue loading, library and store identities, launch and stop actions, download/queue actions, independent source browsing, settings drafts, advanced tools, local backups, achievements, profiles, screenshots, and integrations. Existing native Hydra service restrictions remain enforced; this work does not grant subscription-only services.

Existing pending changes, including the local-backup hero and game-settings tab, were retained. The review makes no claim that every existing working-tree change originated in this pass.

## Verification

- Both Node/main and web TypeScript checks pass using `npm run typecheck`.
- The focused regression run passes **95 tests**, including the existing Big Picture tests, real React input/modal/settings fixtures, launch coordination, native dispatch failures, asynchronous state, settings comparisons, and source-browser policy.
- `node scripts/test-settings-drafts.mjs` passes all **4 tests**, covering explicit saves, cancellation, failures, conflicts, privacy, and navigation.
- `node scripts/test-direct-torrent-protection.mjs` passes all **9 unit tests** and its synthetic backend checks. It does not contact torrent peers.
- `node scripts/test-save-manager-integration.mjs` passes real ZIP/differential backup, preview, validation, guarded restore, safety-snapshot, single-use confirmation, discovery, and duplicate-prevention checks against synthetic files.
- `node node_modules/electron-vite/bin/electron-vite.js build` successfully builds the main process, preload, and renderer, including the integrated Big Picture routes. Existing import-cycle/mixed-import and large-chunk warnings remain; bundling success is not a runtime performance measurement.
- Test logs and other workspace-local verification artifacts are under `.tmp/big-picture-audit/`.

The React fixtures use a simulated DOM and synthetic controller state. Native dispatch tests mock Windows shell/spawn calls. Save-manager integration uses synthetic files and an isolated profile under `.tmp/`; it does not restore personal saves.

## Remaining live validation

After building and installing these changes, test one mouse click and one controller press from both a fresh Big Picture session and after switching input methods. Check game exit, returning to Big Picture, reconnecting a physical controller, and an offline game page. Compare desktop and Big Picture startup using the new launch-stage log entries.

Process detection confirms that Hydra observed a running process; it does not confirm that the game's window is ready or that its loading screen has finished. A game may still be opening when detection times out. Check before retrying. Linux/emulator behavior, hardware-specific rendering or pointer stutter, live website protections, and external service availability need their respective real environments.

This pass does not install the app, change personal preferences or saves, create an installer, or publish a GitHub release.
